  # PrintMan - 거래명세서 출력 기능 추가

  ## 프로젝트 개요
  Delphi 10.3 (RAD Studio 10.3) VCL 애플리케이션.
  포트 8080 HTTP 서버(Indy IdHTTPServer)가 JSON 요청을 받아 FastReport로 프린터 출력.
  소스 루트: src/

  ## 현재 구조 (참고용)
  - unt_HttpReqListen.pas : HTTP 요청 수신 및 라우팅
  - unt_CJ_Korea.pas      : CJ 대한통운 운송장 출력 (do_Print_CJ 메서드 제공)
  - unt_Barcode_Sample.pas: 바코드 출력 (동일 패턴)
  - library/untDatabase.pas     : DB 연결 (dmMain - MSSQL: dbLinkage, Oracle: db_Oracle)
  - library/colib/untGlobal.pas : 전역 타입/변수 (TKorexMaster 등)
  - uJSON.pas             : JSON 파싱 (TJSONObject)

  ## 구현할 기능

  ### 1. JSON 요청 전문 변경 (unt_HttpReqListen.pas 수정)
  기존 POST 요청은 필드 2개(USER_ID, BUNCH_ID)만 처리.
  아래와 같이 print_type 필드를 추가하고 라우팅 처리:

  거래명세서: {"access_key": "", "print_type": "deliverynote_nh01", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
  운송장(CJ): {"access_key": "", "print_type": "invoice_cjdaetong0001", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
  운송장(로젠): {"access_key": "", "print_type": "invoice_logen0001", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}

  라우팅 규칙:
  - print_type이 'deliverynote_'로 시작하면 → 거래명세서 출력
  - print_type이 'invoice_'로 시작하면 → 운송장 출력

  JSON 파싱 시 키는 소문자(user_id, bunch_id, print_type, access_key) 사용.
  기존 nJsonCnt = 2 조건은 제거하고 필드 존재 여부로 분기.

  ### 2. 거래명세서 출력 유닛 신규 추가 (unt_DeliveryNote.pas / .dfm)
  unt_CJ_Korea.pas / unt_Barcode_Sample.pas 와 동일한 패턴으로 작성.

  클래스명: Tfrm_DeliveryNote
  전역 변수명: frm_DeliveryNote

  주요 메서드:
    function do_Print_DeliveryNote(szUSER_ID, szBUNCH_ID, szPrintType: string): Integer;
    → DB에서 거래명세서 데이터 조회 (MSSQL dbLinkage 사용)
    → TDeliveryNoteMaster 레코드 배열에 데이터 구성
    → FastReport 템플릿(bin/deliverynote/deliverynote_nh01.fr3) 로드 후 출력
    → 출력 건수 반환

  ### 3. 거래명세서 데이터 타입 추가 (untGlobal.pas 수정)
  TDeliveryNoteMaster packed record 추가. 포함 필드:
    [DB 컬럼에 맞게 구성 - 아래 '보완 필요' 참고]

  상수 추가:
    DELIVERYNOTE_FR3_PATH = 'deliverynote\';

.
  ### 4. FastReport 템플릿
  bin/deliverynote/deliverynote_nh01.fr3 위치에 배치.
  PDF 양식 기반으로 생성 (별도 제공 예정).

  ### 5. 프로젝트 파일 반영 (PrintMan.dpr / .dproj)
  unt_DeliveryNote.pas 를 프로젝트에 추가.
  unt_HttpReqListen.pas uses 절에 unt_DeliveryNote 추가.
  Application.CreateForm(Tfrm_DeliveryNote, frm_DeliveryNote) 추가.

  ## 에러 처리 패턴 (기존과 동일하게)
  - try/except → Memo_Error.Lines.Add, bin/ERROR_PrintMan_날짜.txt 에 기록
  - gInvPrinting 플래그로 동시 출력 방지

  보완이 필요한 사항

  아래 정보가 없으면 구현이 막히는 부분들입니다.

  [필수]

  1. 거래명세서 DB 테이블 구조
    - 어느 DB(MSSQL teak_bae or Oracle)에서 조회하는지
    - 테이블명 및 조회 SQL (또는 현재 운송장에서 쓰는 쿼리 참고용 제공)
    - bunch_id로 조회하는 방식인지, user_id + bunch_id 조합인지
  2. 거래명세서 출력 필드 목록
    - 제공할 PDF 양식에 어떤 항목이 있는지: 공급자 정보, 품목(품명/수량/단가/금액), 합계, 세액 등
    - 반복 행(품목 라인) 최대 몇 건인지
  3. print_type 코드 체계
    - deliverynote_nh01 에서 nh01의 의미 (농협? 양식 코드?)
    - 향후 거래명세서 양식이 여러 종류 생길 예정인지

  [권장]

  4. 운송장 라우팅 확장 계획
    - invoice_cjdaetong0001, invoice_logen0001 외에 추가 예정인 배송사 코드가 있는지
    - 현재 frm_CJ_Korea.do_Print_CJ만 있는데, 로젠/한진 등은 별도 유닛으로 분리할 예정인지
  5. PDF 양식 파일
    - 약속한 PDF를 공유해주시면 FastReport 템플릿(.fr3) 레이아웃 설계 시 반영 가능
  - library/colib/untGlobal.pas : 전역 타입/변수 (TKorexMaster 등)
  - uJSON.pas             : JSON 파싱 (TJSONObject)
