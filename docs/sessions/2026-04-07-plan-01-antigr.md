

# 거래명세서 출력 기능 추가 — 바이브코딩 프롬프트

## 프로젝트 개요

**PrintMan** — Delphi 10.3 (RAD Studio 10.3) VCL 데스크톱 애플리케이션 임.
포트 8080의 HTTP 서버(Indy `IdHTTPServer`)로 JSON 요청을 수신하고, FastReport 템플릿으로 프린터에 출력한다.
트레이 아이콘 형태로 백그라운드에서 동작하며, DB는 FireDAC MSSQL(`dbLinkage`, DB: `teak_bae`) 과 FireDAC Oracle(`db_Oracle`) 두 가지를 사용한다.

---

## 현재 아키텍처 (기존 코드 구조)

### HTTP 요청 처리 흐름
```
HTTP POST (JSON)
  → unt_HttpReqListen.pas (IdHTTPServer1CommandGet)
  → JSON 파싱 (uJSON.pas)
  → print_type 값으로 분기
  → 출력 유닛의 do_Print() 함수 호출
  → FastReport 렌더링 + 프린터 출력
  → JSON 응답 반환
```

### 핵심 소스 파일
- `src/unt_HttpReqListen.pas` — HTTP 서버, JSON 파싱, 라우팅 담당
- `src/unt_CJ_Korea.pas` — CJ 대한통운 송장 출력 (참조 모델)
- `src/unt_Barcode_Sample.pas` — 바코드 출력 (참조 모델)
- `src/library/untDatabase.pas` — DB 연결 (dmMain 데이터모듈)
- `src/library/colib/untGlobal.pas` — 전역 변수 및 타입 정의

### 기존 JSON 요청 전문 (현재)
```json
{"access_key": "", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
```

### 변경 후 JSON 요청 전문 (신규)
- **거래명세서 출력:**
  ```json
  {"access_key": "", "print_type": "deliverynote_nh01", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
  ```
- **CJ 대한통운 운송장 출력:**
  ```json
  {"access_key": "", "print_type": "invoice_cjdaetong0001", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
  ```
- **로젠 택배 운송장 출력:**
  ```json
  {"access_key": "", "print_type": "invoice_logen0001", "user_id": "jjh103", "bunch_id": "20260312_194351_F04A1"}
  ```

### 기존 DB 연결 정보
- `dmMain.dbLinkage` — FireDAC MSSQL, `jjh103.iptime.org:64707`, DB: `teak_bae` (송장 정보 조회용)
- `dmMain.db_Oracle` — FireDAC Oracle, `221.149.104.164:31521/ORCL` (배송사 연동)

## 구현 요청 사항

### 1. `unt_HttpReqListen.pas` 수정 — JSON 라우팅 추가

POST 요청 JSON에서 `print_type` 필드를 읽어 아래와 같이 분기 처리한다:

```
print_type = "deliverynote_nh01"     → frm_DeliveryNote_NH01.do_Print(user_id, bunch_id)
print_type = "invoice_cjdaetong0001" → frm_CJ_Korea.do_Print_CJ(user_id, bunch_id)  (기존)
print_type = "invoice_logen0001"     → [추후 구현 예정, 현재는 미지원 응답 반환]
print_type 없거나 미지원 값         → 에러 JSON 응답 반환
```

JSON 키 파싱 예시 (기존 `uJSON.pas` 스타일):
```delphi
szPRINT_TYPE := VarToStrDef(obj_json.getString('print_type'), '');
szUSER_ID    := VarToStrDef(obj_json.getString('user_id'), '');
szBUNCH_ID   := VarToStrDef(obj_json.getString('bunch_id'), '');
```

### 2. `src/unt_DeliveryNote_NH01.pas` / `.dfm` 신규 생성

`unt_CJ_Korea.pas`의 구조를 참고하여 동일한 패턴으로 작성한다.

**공개 인터페이스:**
```delphi
function do_Print(szUSER_ID, szBUNCH_ID: string): Integer;
```

**DB 조회 (dbLinkage 사용, MSSQL):**
```sql
SELECT *
FROM   DMT_PRT_DELIVERYNOTE   -- 거래명세서용 테이블명 (확인 필요)
WHERE  USER_ID  = :user_id
AND    BUNCH_ID = :bunch_id
AND    RSLT_STATE = 'R'
ORDER  BY SORT_NUM
```

**출력 완료 후 상태 업데이트:**
```sql
UPDATE DMT_PRT_DELIVERYNOTE
SET    RSLT_STATE   = 'P',
       PRINT_COUNT  = PRINT_COUNT + 1
WHERE  USER_ID  = :user_id
AND    BUNCH_ID = :bunch_id
AND    RSLT_STATE = 'R'
```

**FastReport 연동:**
- `.fr3` 파일 경로: `gszHomePath + 'invoice\' + 'deliverynote_nh01.fr3'`
- `TfrxMemoView(FindObject('필드명')).Text := 데이터` 방식으로 DB 데이터를 템플릿에 세팅
- `szReport.Print` 으로 출력 (100장 단위 페이지 단위 출력, unt_CJ_Korea.pas 참고)
- 전역 플래그 `gInvPrinting` 을 사용해 동시 출력 방지

### 3. `bin/invoice/deliverynote_nh01.fr3` — FastReport 템플릿 신규 생성

거래명세서 양식은 별도 PDF 파일로 제공된다. PDF를 참고해 FastReport 디자이너에서 동일한 양식의 `.fr3` 템플릿을 만든다.

**거래명세서에 출력할 주요 항목 (DB 컬럼 및 MemoView 이름은 확인 후 작성):**
- 공급자 정보: 상호, 주소, 전화번호, 사업자등록번호
- 수신자 정보: 상호, 주소
- 거래 일자, 품목 리스트 (품명, 수량, 단가, 금액), 합계 금액
- 비고

신규 유닛 `unt_DeliveryNote_NH01` 을 프로젝트에 추가 등록한다.

## 공통 규칙 및 패턴

- **에러 처리**: `try-except`로 감싸고, 에러 발생 시 `bin/ERROR_PrintMan_YYYYMMDD_HHMMSS.txt` 에 저장
- **전역 플래그**: 출력 시작 전 `gInvPrinting := True`, 종료 시 `finally` 블록에서 `gInvPrinting := False`
- **프린터 선택**: `unt_CJ_Korea.pas`의 `Get_Valid_Printer` 방식 동일하게 적용
- **문자 인코딩**: 소스파일은 UTF-8 BOM으로 저장
- **JSON 응답 포맷**:
  ```json
  { "code": "SUCCESS", "print_cnt": 3, "message": "출력완료" }
  ```
  에러 시:
  ```json
  { "code": "ERROR", "print_cnt": 0, "message": "에러 내용" }
  ```

> - 거래명세서 데이터를 저장하는 테이블명은 무엇인가? (예: `DMT_PRT_DELIVERYNOTE`)
> - 어느 DB에 있는가? `dbLinkage`(MSSQL `teak_bae`) 인가, `db_Oracle` 인가?
> - 테이블의 컬럼 목록과 타입은 무엇인가?

### [필수] 거래명세서 PDF 양식 제공

FastReport 템플릿(`.fr3`) 설계를 위해 PDF 파일을 실제로 첨부해야 한다.

> - 거래명세서 PDF 파일을 첨부해 주세요.
> - PDF의 섹션 구분, 반복 행(품목 리스트), 합계 영역 구조를 알려주세요.

### [권장] 기존 print_type 없는 요청의 하위 호환성

현재 `unt_HttpReqListen.pas`는 `print_type` 없이 `user_id`, `bunch_id` 만 받아 처리한다.
`print_type` 필드를 필수로 할 것인지, 혹은 없을 경우 기존 동작(CJ 대한통운 출력)으로 fallback 할 것인지 결정 필요.

> - `print_type` 없는 기존 요청을 CJ 대한통운으로 기본 처리할 것인가?
> - 아니면 에러 응답을 반환할 것인가?

### [권장] 로젠 택배 (`invoice_logen0001`) 구현 시점

현재 요청 전문에 로젠 택배 `print_type`이 포함되어 있으나, 구현 대상인지 여부가 불명확하다.

> - 이번 작업에서 로젠 택배도 함께 구현할 것인가?
> - 아니면 라우팅만 예약해두고 "미지원" 응답 반환으로 처리할 것인가?

### [선택] 프린터 선택 방식

현재 CJ 대한통운은 `cxGrid` UI로 프린터를 선택한다.
거래명세서도 동일한 UI를 재사용할 것인지, 아니면 별도 설정(settings.ini 등)으로 분리할 것인지.

> - 거래명세서와 운송장을 서로 다른 프린터에 출력할 필요가 있는가?
